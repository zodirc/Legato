本地文件播放

管线为 FileSource → FFmpegDemuxer → 每路包队列 → FFmpegSwDecoder → PCM 环或帧队列 → 音频输出线程。打开在会话 IO 线程上。Player::io_main 注入 AudioMasterClock 和 LinuxAudioSink；没有音频流，或设备都打不开且预设允许回落时，改为 MonotonicClock。控制线程写 serial、目标位置，以及 precise 模式下的丢帧门槛。

1. 打开与队列

http:// 与 https:// 由 HttpSource 经 libcurl 取字节，登记的 scheme 由 CallbackSource 取字节，然后都进入同一个 FFmpegDemuxer。播放用的 FFmpeg 仍关闭网络。没有 Accept-Ranges: bytes 时 source_seekable 为 0，Seek 失败，会话不进入 error。FFmpegDemuxer 使用 AVFMT_FLAG_CUSTOM_IO，字节来自 DataSource。解复用线程按流把包放进队列。时长上限是预设的 buffer_max_s，字节上限是这个秒数乘以 1 MiB/s。视频帧队列容量 8。包和帧带 serial。存在音频流时，LinuxAudioSink 先打开 PipeWire，失败再打开 ALSA PCM 设备，输出为交错 S16。ALSA 请求 100 毫秒缓冲和 20 毫秒周期。两条都失败时，audio_fallback 为真的预设改用按样本时长推进的 Sink，并上报 audio_fallback。music 和 realtime 报 audio_device_unavailable。有音频时，VideoPresenter::pace_audio 按音频位置挑帧，晚过一帧的计入 dropped_frames。GlVideoSink 保留当前帧。legato_render_frame 在调用方的 GL 上下文里把这一帧上传到纹理并画到给定的 FBO，同一帧只上传一次。预设 video 为假时，FFmpegDemuxer::discard_video 使解复用不交出视频包，也不打开视频解码器。

2. 主时钟与流结束

音频输出线程从 PCM 环取出样本再写入设备。主时钟在 AudioMasterClock::observe_snapshot 计算。snd_pcm_status 一次取出 delay 和硬件时间戳。时间戳可用且单调、与现在相差不超过 500 毫秒时，位置是 origin_us + (written_frames - delay_frames) * 1000000 / rate + (now - tstamp)。否则只留 delay 那一项。来源记入 audio_clock_source。回落路径按已写样本推进 position_us，会话时钟是单调时钟。首次写入成功后，输出线程把首帧写入通知环，控制线程调用 media_first_frame。EOF 之后取出重采样残余样本，再排空设备缓冲。排空期间若暂停或 Seek 已经置位，不发送 EOS。输出线程看到新 serial 后清零写入帧数和首帧标记。precise 丢掉 PTS 小于目标的视频帧和 PCM 帧。keyframe 与 nearest 不丢。连续 Seek 在控制线程合并，只执行最新一次。av_seek_frame 期间目标变了，解复用线程不 flush，接着定位到最新位置。呈现时帧的 serial 与当前不一致，这一帧不交给 Sink。

3. 传输控制

暂停调用 AudioSink::drop。设备欠载才 snd_pcm_recover。包队列见底时输出线程写入卡顿通知，控制线程把 state 变为 buffering，stall_count 加一。FilePlayback::stop 不能在持有 Player::mu_ 时执行，因为解复用线程调用 media_failed 需要同一把锁。输出线程不拿这把锁。
